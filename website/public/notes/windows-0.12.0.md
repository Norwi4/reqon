# Reqon 0.12.0 — оформление Windows

Реализованы требования `DESIGN_GUIDELENS.md`, `icons.md` и `reqon-ui-states/README.md`. Изменения интерфейса включаются только на Windows. Приложение остаётся нативным Qt Widgets; сетевой слой, формат коллекций и схема базы данных не менялись.

## Изменения

- Единая тёмная палитра, границы, отступы, hover/focus и активные состояния. Оранжевая линия активной вкладки — 2 логических px; основные действия — синие.
- Оригинальная иконка Reqon слева в TitleBar: 24 px внутри кнопки 36 px, tooltip `Reqon — Home`. Нажатие использует существующее действие Home: открывает Collections, сохраняя текущие вкладки. Высота TitleBar остаётся 48 px.
- Строки дерева высотой 30 px, семантические цвета HTTP-методов/gRPC, счётчики запросов коллекций, подсветка совпадений поиска и кнопка сворачивания дерева. Сохранены переименование, вложенность, меню, drag & drop и действия коллекций.
- Крестик закрытия активной вкладки виден постоянно, остальных — при наведении. Оранжевая точка показывает ожидающие автосохранения изменения или ошибку сохранения. Длинные названия сокращаются; полное название доступно в tooltip.
- Глобальный поиск `Ctrl+K` по коллекциям, папкам, запросам, примерам, локальным черновикам и последним 200 записям истории. Стрелки выбирают результат, Enter открывает, Escape закрывает. Используются текущая база и дерево, отдельный индекс не создаётся. Показываются первые 100 совпадений с явной подсказкой об ограничении.
- В редакторе выделяется активная строка; JSON проверяется после паузы ввода. Ошибка показывается внутри редактора и подчёркивается без модального окна. Форматирование JSON поддерживает Undo; XML остаётся читаемым и получает подсветку тегов.
- Разделитель Request/Response имеет заметный hover, курсор изменения размера и двойной клик для пропорции 60/40. Минимальные размеры защищают содержимое от полного схлопывания.
- Состояния до отправки и после завершённого пустого ответа различаются. Статус, время и размер берутся из результата; отсутствующие метрики не подставляются. Длина текста ошибки не выдаётся за размер ответа сервера.
- Ошибки сохраняют исходную диагностику, статус, metadata и trailers. HTTP-тело остаётся во вкладке Body; дополнительное объяснение находится в Status.

## Иллюстрации и иконки

Для системных иконок используется `Reqon_Developer_Icons_v2/windows/reqon.ico`, для TitleBar — оригинальный `svg/reqon-transparent.svg`. ICO включён в EXE, установщик, значок окна и ярлыки; AppUserModelID приложения и ярлыков — `Norwi4.Reqon`. Доступны размеры 16, 24, 32, 48, 64, 128 и 256 px.

Из `reqon-ui-states` используются оригинальные тёмные SVG, обычно размером 128 логических px:

| Состояние | Иллюстрация |
|---|---|
| Запрос ещё не отправлен | `response-ready-to-send` |
| Завершённый ответ без тела | `response-no-content` |
| gRPC UNAVAILABLE / HTTP 503 | `error-service-unavailable` |
| Типизированная ошибка подключения / DNS / TLS / тайм-аута | Соответствующий `error-*` |
| Нет открытых вкладок | `request-create-new` |
| Нет коллекций / истории / совпадений поиска | `collections-empty`, `activity-no-requests`, `search-no-results` |

Картинка выбирается по состоянию, структурированному коду или типу исключения. Предположение старого обработчика о TLS на основании текста не используется как основание для выбора иллюстрации. Если gRPC сообщает только UNAVAILABLE без типизированной причины, показывается общее состояние недоступности и полная диагностика. Для ошибок без подходящей иллюстрации, например FAILED_PRECONDITION, используется нейтральный фирменный знак Reqon.

При недостатке высоты иллюстрация скрывается, а текст остаётся. Успешный payload никогда не заменяется картинкой. Все 14 тёмных SVG включены в поставку; `data-empty`, `folder-empty` и `response-success` зарезервированы для соответствующих отдельных представлений и не навязываются существующему просмотру тела ответа.

## Совместимость и установка

Установщик: `dist/Reqon-Setup-0.12.0-win64.exe`. Portable-архив: `dist/Reqon-windows.zip`. Версия Windows — 0.12.0; версия других платформ остаётся 0.11.0.

Сохранён прежний AppId установщика для обновления существующей установки. При новой установке предлагается `%LOCALAPPDATA%/Programs/Reqon`; папку можно выбрать в мастере. При обновлении предлагается прежний путь. Заменяются старый EXE и ярлыки Getman. Данные остаются в `%APPDATA%/Getman/getman.sqlite3`: внутренние имена QApplication/организации Getman намеренно сохранены. Для отдельной базы доступен `Reqon.exe --data-dir "D:\Reqon workspace"`.

Сетевые настройки сохранены, включая `Enable server certificate verification = OFF` по умолчанию и явно сохранённое пользователем значение ON. Рабочие VPN-адреса для проверок не использовались.

## Проверки

- Полный набор: **71 тест успешно**, включая HTTP/gRPC, TLS/mTLS, reflection, генерацию примера сообщения, curl/grpcurl, отмену, автосохранение, импорт/экспорт, дерево, вкладки и resize.
- После финальной правки выбора иллюстраций/подсказки поиска: **8 Windows UI-тестов успешно**, включая реальное сочетание Ctrl+K.
- Приложение действительно запускалось через Qt Widgets. Проверены снимки обычного и компактного окна, ответов и ошибок, JSON-валидации и поиска. Проверено масштабирование 100%, 125%, 150%, 200%; TitleBar остаётся 48 логических px, компактное окно — 1000×700.
- Проверена загрузка всех 14 SVG. Ресурсы в собранном приложении сверены побайтно с исходными файлами.
- PyInstaller и Inno Setup успешно собрали EXE/ZIP/установщик. Проверены версии и многоразмерные иконки в PE-ресурсах EXE и установщика.
- Собранный `Reqon.exe` дважды запускался и штатно закрывался через оконное сообщение в отдельном временном профиле. Код выхода 0, вкладки восстанавливаются, `PRAGMA integrity_check = ok`, история пуста. Визуально проверен снимок именно собранного EXE.
- Проверка прежней платформенной ветки успешно выполнена отдельным процессом на Windows. Это не запуск Linux: Linux/Astra в этой задаче не пересобирались и не проверялись на реальной ОС.

Логи находятся в `build/windows-012-*.log`, снимки — в `docs/ui/reqon-windows-*.png`. Сведения о поставке и SHA-256: `dist/Reqon-0.12.0-build-info.json`, файлы `.sha256` рядом с артефактами.

## Ограничения

- Светлой темы в исходном приложении нет; новая тема в этой задаче не добавлялась.
- Фактическая установка поверх пользовательской рабочей версии не выполнялась. Проверены конфигурация обновления, сборка установщика и запуск содержащегося в нём приложения; пользовательская установка и база не изменялись.
- Системные значки проверены по ресурсам и runtime-иконке; отдельная ручная проверка закреплённого значка панели задач/Alt+Tab не выполнялась.
- Не добавлялись новые страницы для зарезервированных иллюстраций, облачные функции или возможности, отсутствовавшие в сетевом слое. Windows-дизайн не переносился на другие ОС.
- Автоматическая проверка отклонила очистку одной временной тестовой папки (`%TEMP%/reqon-packaged-smoke-q8vw2maf`, причина `blocked by policy`). Там осталась только тестовая SQLite-база без пользовательских данных. Последующий исправленный тест успешно очищает собственный временный профиль.
