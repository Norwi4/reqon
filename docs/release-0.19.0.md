# Reqon 0.19.0

Актуальная версия для Windows x64, Linux x86-64 и Astra Linux 1.8. Встроенный Rust CLI — **0.14.1**; устанавливать его отдельно для GUI не требуется.

- Обычные HTTP-запросы и все четыре типа gRPC выполняются через Rust-движок. Регрессионные пакеты запускаются через **File → Run regression package…** (`Ctrl+Shift+R`), с отменой и HTML/JSON/JUnit-отчётами.
- Сохранённые вкладки создают редакторы при первом открытии. Активная вкладка готова сразу, остальные сохраняют свои данные и порядок.
- Ускорены применение тем, подсветка и проверка больших JSON-документов, автодополнение и автосохранение. Большие ответы показываются частями; Copy, Save и поиск используют полный ответ.
- Повторные gRPC-вызовы переиспользуют соединения и protobuf-дескрипторы с учётом endpoint, TLS и metadata. Ошибки, дедлайны и Refresh сбрасывают кэш; отмена одного запроса не завершает соседний.
- Обновления метаданных коллекций сохраняют существующие узлы дерева. Проверены коллекции из 50 000 и 100 000 запросов.
- Стабилизирован воспроизведённый сбой TLS: циклическая сборка мусора Python выполняется в GUI-потоке.
- Linux-сборки обновлены до той же версии, что и Windows; проверены запуск, изменение размера окна, HTTP/HTTPS и восстановление вкладок.

## Измерения

| Сценарий | До | После |
| --- | ---: | ---: |
| Запуск EXE с 20 сохранёнными вкладками | 13,29 с | 1,70 с |
| RSS при готовности окна с 20 вкладками | 462 MiB | 185 MiB |
| Повторное обновление дерева из 100 000 запросов | 4510 мс | 452 мс |
| Прогретый gRPC Send, p50 / p95 | 32,74 / 101,29 мс | 18,22 / 48,27 мс |
| Reflection при 25 последовательных вызовах | 50 обращений | 2 обращения |

Локальные измерения на Windows 11, Python 3.14.0 и Qt 6.12.0. Запуск EXE — медиана трёх новых процессов, до видимого отвечающего окна, с JSON-телами по 187 KB; дисковый кэш ОС не очищался. Дерево — один замер Qt offscreen с принудительным полным rebuild для сравнения. gRPC — 25 реальных GUI Send на локальном plaintext-сервере, первый вызов исключён из прогретых показателей. Результаты зависят от оборудования и данных.

Первое открытие отложенного редактора занимает дополнительное время. Первичная загрузка редактируемого JSON около 10 MiB по-прежнему занимает около 7,7 с, RSS после работы достигает 620 MiB; первое построение дерева из 100 000 запросов — около 4,6 с. Кэш gRPC ограничен и имеет TTL 60 секунд; при прозрачном переподключении схема обновится после TTL или Refresh. Временные proxy/insecure TLS/keylog relay не кэшируются.

## Проверки и загрузки

Windows: 208 различных тестовых случаев прошли. Linux: 206 прошли, 2 пропущены из-за отсутствия grpcurl и платформенного Windows-теста; resize отдельно проверен под X11. Rust: 7 unit tests прошли. Финальная TLS-проверка: 20 повторов без сбоя. Готовые Windows-сборки проверены в Light/Dark с JWT RS256, бинарным multipart и восстановлением данных; Linux DEB и portable — запуском и восстановлением, DEB дополнительно — HTTP/HTTPS с проверкой CA.

В **Assets** доступны:

- `Reqon-Setup-0.19.0-win64.exe` — установщик Windows.
- `Reqon-0.19.0-windows-x86_64.zip` — переносимая Windows-сборка.
- `Reqon-0.19.0-linux-x86_64.tar.gz` — переносимая Linux-сборка, glibc ≥ 2.36.
- `reqon_0.19.0_astra1.8_amd64.deb` — пакет Astra Linux 1.8.
- `SHA256SUMS.txt` — контрольные суммы четырёх сборок.

Python и движок включены в сборки. Обновление приложения сохраняет существующую пользовательскую базу Reqon. Linux-пакеты собраны и проверены на Astra Linux 1.8 с Python 3.11 и PySide6 6.11.3; другие дистрибутивы отдельно не проверялись.
