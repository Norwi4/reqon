# Запуск коллекций из Windows CLI

GUI и CLI используют одну библиотеку Reqon. CLI читает коллекцию из указанной папки, не создаёт desktop-профиль и не сохраняет изменения переменных в исходники.

```powershell
./target/release/reqon-cli.exe run ./api --env CI --report-json results.json --report-junit results.xml --report-html results.html
```

Коллекция содержит `reqon.json`, `bruno.json` или `opencollection.yml`. Выполняются сохранённые HTTP, gRPC и WebSocket-запросы через общий Engine. HTTP-статусы проверяются явно в скриптах/assertions: сам по себе HTTP 500 не заменяет проверку ожидаемого статуса.

## Данные CSV и JSON

```powershell
./target/release/reqon-cli.exe run ./api --data users.csv --env CI --report-html results.html
```

Одна строка данных означает одну итерацию выбранной коллекции. Если задан `--data`, количество строк заменяет `--iterations`, как в Kurlo. В отчёте `iteration` и `data_row` нумеруются с 1.

CSV содержит заголовок и хотя бы одну строку:

```csv
user,role,note
ada,admin,"contains a comma, and text"
grace,reader,"quotes: ""example"""
```

Поддерживаются UTF-8 с BOM или без него, CRLF/LF, кавычки, запятые и переносы строк внутри кавычек. Разделитель — запятая. Значения CSV остаются строками. Имена колонок обрезаются по краям; пустые и повторяющиеся имена, а также несовпадающее число полей отклоняются.

JSON сохраняет типы значений в `pm.iterationData`:

```json
[
  {"user": "ada", "active": true, "limit": 10},
  {"user": "grace", "active": false, "limit": 5}
]
```

Также принимаются объекты `{"data": [...]}` и `{"rows": [...]}`. Каждая строка должна быть объектом. Лимиты: 16 МиБ на файл, 10 000 строк и 1024 колонки в строке. Ошибка входного файла завершает CLI с кодом 2 до отправки запросов.

Данные подставляются в URL, заголовки, Auth и тела через `{{user}}`. В строковых подстановках `null` становится пустой строкой, объекты и массивы — JSON. В скриптах доступны:

```javascript
const user = pm.iterationData.get("user");
const hasLimit = pm.iterationData.has("limit");
const row = pm.iterationData.toObject(); // также toJSON()
const sameRow = bru.getIterationData();
const index = pm.info.iteration;       // с 0, как в Postman
const total = pm.info.iterationCount;

pm.test("active is boolean", () => {
  pm.expect(pm.iterationData.get("active")).to.be.a("boolean");
});
```

`iterationData` доступна только для чтения; `get`, `toObject`, `toJSON` и `bru.getIterationData` возвращают копии. Она сохраняется в pre/post-скриптах и вложенном `bru.runRequest`.

## Переменные и последовательные цепочки

По умолчанию `--parallel 1`. Запросы сортируются по папке и сохранённому `seq`; равные значения сохраняют исходный порядок. Изменения окружения, глобальных, коллекционных и runtime-переменных передаются следующему запросу и следующей итерации. Изменения отменённого запроса отбрасываются.

Строка данных накладывается поверх подготовленных переменных перед каждым запросом, включая `--var` и `--secret`. Она не записывается в окружение. Если колонка отсутствует в следующей строке, снова используется значение нижележащего scope. Изменения через `pm.environment.set` остаются в окружении, но одноимённая колонка продолжает перекрывать их при подстановке. `pm.environment.get` читает окружение, `pm.iterationData.get` — исходную строку.

`bru.runner.setNextRequest` / `pm.execution.setNextRequest` выбирают только среди отфильтрованных запросов. Имя должно однозначно определять запрос; можно указать `Папка/Имя`. `skipRequest` пропускает отправку, `stopExecution` останавливает прогон. Общий `--max-steps` ограничивает количество запускаемых запросов, включая повторения и переходы; по умолчанию 10 000.

## Папки и теги

```powershell
./target/release/reqon-cli.exe run ./api --folder Billing/Refunds --tag smoke --tag regression
```

- `--folder` выбирает папку и все её подпапки. `Billing` не совпадает с `Billing2`.
- `--tag` выбирает тег самого запроса.
- Оба флага можно повторять: внутри группы действует «ИЛИ», между папками и тегами — «И».
- Сопоставление точное, с учётом регистра; маски не используются. В путях принимаются `/` и `\`, путь задаётся относительно коллекции.
- Пустой результат выбора — ошибка с кодом 2. Нечитаемые файлы коллекции также считаются ошибкой подготовки.

## Параллельные запросы

```powershell
./target/release/reqon-cli.exe run ./api --folder Independent --data users.json --parallel 4 --delay 50 --stop-on-error
```

`--parallel N` допускает от 1 до 64 одновременно выполняющихся запросов. При N > 1 запросы текущей итерации выполняются параллельно; следующая итерация начинается после завершения текущей. Очередь создаётся по мере освобождения мест, отчёт сохраняет порядок коллекции.

Каждый параллельный запрос получает отдельный снимок исходных переменных. Изменения его скриптов действуют внутри этого запроса и попадают в его результат, но не передаются соседям или следующей итерации. Сетевые клиенты, cookies и кэш токенов остаются общими для прогона. Поэтому зависимые цепочки, в том числе вход и использование полученных cookies, запускайте с `--parallel 1`. `setNextRequest` в параллельном режиме приводит к ошибке с указанием перейти в последовательный режим; новые задания после обнаружения ошибки не запускаются.

`--delay MS` при параллельном запуске задаёт минимальный интервал между стартами запросов всего прогона. В последовательном режиме это пауза после завершения предыдущего запроса. Максимум — один час.

`--stop-on-error` останавливает постановку новых запросов после первой обнаруженной ошибки. Уже начатые запросы завершаются и сохраняются в отчёте. `stopExecution` действует аналогично. Ctrl+C/Ctrl+Break отменяют и активные запросы, и очередь; отмена не ждёт сетевых таймаутов или окончания JS-цикла.

## Отчёты и секреты

| Флаг | Результат |
|---|---|
| `--json` | JSON в stdout |
| `--report-json PATH` | Полный JSON-отчёт |
| `--report-junit PATH` | XML для CI с итерацией, папкой и строкой данных в имени проверки |
| `--report-html PATH` | Самостоятельная HTML-страница: сводка, таблица и раскрываемые ответы, заголовки, тесты, console |

HTML работает без сети и JavaScript. Содержимое ответов отображается как текст, а не исполняется. Все три формата строятся из одного отчёта после маскирования секретов. Исходные строки набора данных в отчёт целиком не добавляются.

```powershell
$env:CI_API_TOKEN = "local-test-token"
./target/release/reqon-cli.exe run ./api --secret TOKEN=CI_API_TOKEN --report-html result.html
```

Для секретов используйте поля Auth, переменные окружения с отметкой Secret или `--secret`. Если строка данных перекрывает переменную, уже помеченную Secret, её новое значение также маскируется. Произвольные колонки и строки в телах автоматически секретными не становятся.

При отмене сохраняются завершённые результаты и результаты активных отменённых запросов; ещё не запущенные задания не добавляются. В JSON устанавливается `cancelled: true`; JUnit отмечает отменённые запросы как skipped и добавляет ошибку всего запуска. Явный `skipRequest` также отображается как skipped и сам по себе не проваливает прогон.

| Код | Значение |
|---|---|
| 0 | Прогон завершён, проверки прошли |
| 1 | Ошибка запроса, теста или выполнения; исчерпан лимит шагов |
| 2 | Некорректные аргументы, данные, коллекция или ошибка записи отчёта |
| 130 | Прогон отменён пользователем |


При реализации использованы как ориентиры зафиксированные исходники Kurlo: [данные CLI](https://github.com/stormhop/kurlo/blob/57ae34d7e7cac1809a3a8d56efd6774f9657f99a/apps/desktop/internal/api/cli_data.go), [планировщик GUI](https://github.com/stormhop/kurlo/blob/57ae34d7e7cac1809a3a8d56efd6774f9657f99a/apps/desktop/frontend/src/lib/stores/features/collectionRunner.ts) и [HTML-отчёт](https://github.com/stormhop/kurlo/blob/57ae34d7e7cac1809a3a8d56efd6774f9657f99a/apps/desktop/frontend/src/lib/runnerReport.ts). Код Go/TypeScript не копировался; CSV читает библиотека `csv`, выполнение реализовано в общем Rust-ядре Reqon.
