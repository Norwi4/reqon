# Reqon 0.13.8 — Windows x64

Установщик: `dist/Reqon-Setup-0.13.8-win64.exe`. Переносимая сборка: `dist/Reqon-windows.zip`.

## General

Шестерёнка / Ctrl+, открывают Settings внутри главного окна. General и Proxy активны, остальные разделы остаются неактивными. Все настройки хранятся локально и сохраняются автоматически. Внешний вид основан на пользовательских скриншотах 36–39, поведение — на [документации General в Postman](https://learning.postman.com/docs/getting-started/installation/settings/general-settings).

### Сеть и файлы

- HTTP/1.x отправляет HTTP/1.1 и принимает ответы HTTP/1.0/1.1. Auto согласует HTTP/2 по ALPN для HTTPS, иначе использует HTTP/1.1. HTTP/2 требует HTTP/2, без скрытого перехода на HTTP/1; для незашифрованного соединения используется prior knowledge (h2c).
- Request timeout задаётся в миллисекундах и ограничивает весь HTTP-запрос, включая перенаправления и чтение тела. Ноль отключает ограничение. Для gRPC используется deadline.
- Max response size ограничивает загрузку и распаковку HTTP-ответа; gRPC ограничивает сообщение и суммарный поток. Ноль снимает ограничение.
- SSL certificate verification управляет проверкой сертификата и имени сервера для HTTP/gRPC. По умолчанию OFF, как ранее просил пользователь. TLS-шифрование при этом остаётся включённым, если выбран TLS.
- SSL/TLS key log пишет ключи сеансов в локальный `logs/tls-keys.log`. Кнопка экспорта сохраняет копию в выбранный файл. Эти ключи позволяют расшифровывать соответствующий TLS-трафик; журнал создаётся только при включённой настройке и не попадает в экспорт коллекций.
- Cookies сохраняются в локальном `cookies.txt` и используются с учётом домена, пути, Secure и срока действия. Disable cookies отключает чтение/обновление cookie jar. Явный заголовок Cookie остаётся частью самого запроса.
- Working directory задаёт базу относительных путей. В HTTP → Body добавлен режим `file`, отправляющий содержимое выбранного файла. Read files outside working directory разрешает или запрещает пути вне папки, включая переходы через `..` и символические ссылки. Явно выбранные ранее сертификаты и определения protobuf используют прежние правила доступа.
- Request validation проверяет JSON до отправки. В HTTP → Settings можно указать локальный JSON Schema либо OpenAPI JSON: подбирается операция по методу/пути и проверяется JSON requestBody. Поддерживаются внутренние `$ref`; удалённые схемы не загружаются. Это локальная проверка, без облачных API Postman. Обязательная сериализация protobuf выполняется независимо от переключателя.
- Response format detection: Auto учитывает Content-Type (JSON/XML), JSON принудительно пытается отформатировать тело как JSON. Исходные данные сервера не заменяются, если форматирование невозможно.

Настройки действуют для новых отправок и рефлексии. В Settings конкретного HTTP/gRPC-запроса есть Override General settings: он сохраняет индивидуальные значения. Существенные ранее сохранённые отклонения от прежних значений по умолчанию и импортированные cURL/gRPCurl сохраняются как индивидуальные настройки.

### Заголовки и интерфейс

- Send no-cache header добавляет Cache-Control: no-cache; Send Postman Token header — новый UUID в Postman-Token. Явные заголовки пользователя имеют приоритет.
- Automatically follow redirects работает для HTTP. При переходе на другой origin автоматически удаляются Authorization/Cookie/Host; cookie jar заново выбирает подходящие cookies.
- Ссылки в ответе открываются как новый GET-запрос по Ctrl+щелчку или через контекстное меню. Retain headers when clicking on links переносит явно заданные заголовки и авторизацию исходного запроса.
- Always open sidebar item in new tab: ON открывает отдельную вкладку; OFF заменяет предыдущую вкладку предпросмотра. Изменённые и выполняемые запросы защищены от замены. Повторный выбор уже открытого элемента активирует его вкладку.
- Show icons with tab names и Two-pane view немедленно меняют вкладки и расположение запроса/ответа.
- Variable autocomplete дополняет `{{имя}}` из доступных переменных в адресе, теле, авторизации и таблицах.
- Default documentation editor переключает описание коллекции между редактором Reqon с форматированием и исходным Markdown. Хранилище описания остаётся единым; внешний контент не загружается.

### Редактор, язык и сохранение

- Font Family выбирает первый доступный шрифт из списка; Font Size — размер в px. Есть живой предпросмотр и название реально выбранного шрифта.
- Inter и JetBrains Mono загружаются до применения стилей. Шрифт явно задаётся редактору и его QTextDocument; ошибки ответа также используют шрифт кода. По умолчанию Inter для интерфейса, JetBrains Mono 13 px для кода; файлы и лицензии OFL включены в установщик.
- Indentation count/type влияют на Tab, Shift+Tab, новую строку и форматирование JSON. Auto close brackets/quotes можно включать независимо. Reset возвращает настройки редактора по умолчанию.
- Language переключает основные элементы интерфейса и настройки между English и Русский. Названия пользовательских данных, значения протоколов и сообщения серверов не переводятся.
- Autosave по умолчанию ON. OFF прекращает автоматическую запись изменений запросов; Ctrl+S сохраняет их вручную. Always ask when closing unsaved tabs управляет вопросом о несохранённых изменениях при выключенном автосохранении и по умолчанию OFF. При включённом автосохранении закрытие остаётся без лишнего подтверждения.
- Пункты облачного перехода в веб-Postman и отправки телеметрии отсутствуют: Reqon остаётся локальным приложением.

## Скриншот 40

Новые gRPC-запросы создаются с пустым телом и одной строкой. Compose message — настоящая подсказка редактора, не содержимое запроса. Она исчезает при вводе и появляется после очистки. Содержимое ранее сохранённых запросов не очищается.

Вертикальные разделители вкладок имеют отступы по 9 px сверху и снизу; горизонтальная нижняя граница ряда вкладок сохранена.

## Проверка

Использованы временные базы и локальные HTTP/HTTPS, HTTP/2, gRPC и proxy-серверы. Проверены новые настройки, сохранение/экспорт коллекций, cURL/gRPCurl и Proxy. Рабочие VPN-сервисы не использовались. Выпуск и установщик подготовлены только для Windows.
