# Reqon 0.13.7 — Windows x64

Установщик: `dist/Reqon-Setup-0.13.7-win64.exe`. Переносимая версия: `dist/Reqon-windows.zip`.

## Settings

Шестерёнка справа сверху и Ctrl+, открывают настройки поверх рабочего пространства: это дочерний Qt-виджет внутри главного окна, без отдельного окна в панели задач. Закрытие — крестиком или Escape. Панель адаптируется к размеру окна и прокручивается по вертикали.

Пункты General, Themes, Shortcuts, Data, Add-ons, Certificates, Update и About пока неактивны. Реализован Proxy; ориентиры — пользовательские скриншоты 34–35 и [описание настроек Postman](https://learning.postman.com/docs/getting-started/installation/settings/proxy-settings).

## Proxy

- Системный прокси Windows, включая обнаружение PAC через Qt/Windows. Настройки операционной системы не изменяются.
- Независимый переключатель HTTP_PROXY, HTTPS_PROXY, NO_PROXY; также учитывается ALL_PROXY. По умолчанию системный прокси и переменные окружения включены, пользовательский прокси выключен.
- Пользовательский прокси: HTTP CONNECT, SOCKS5, SOCKS5H, SOCKS4, SOCKS4A; адрес, порт и выбор HTTP/HTTPS-запросов. Для gRPC переключатель HTTP соответствует соединению без TLS, HTTPS — с TLS.
- Пользовательские настройки имеют приоритет. Исключённые типы запросов и адреса из Proxy bypass идут напрямую. При выключенном пользовательском прокси используются переменные окружения, затем системный прокси. NO_PROXY применяется к автоматическому выбору, а пользовательский режим использует собственный список исключений.
- Авторизация Basic для HTTP-прокси; имя/пароль для SOCKS5. SOCKS4/4A передают только имя пользователя. SOCKS5 и SOCKS4 разрешают DNS локально, SOCKS5H и SOCKS4A — на прокси. Поддерживаются доменные суффиксы, шаблоны `*.example.com`, IP/CIDR, `<local>` и порты в исключениях.
- Авторизация системного/автоматического прокси задаётся в Default proxy configuration. Учётные данные из URL переменной окружения имеют приоритет над этой парой имя/пароль.
- Настройки сохраняются автоматически в локальной базе. Пароли защищаются Windows DPAPI для текущего пользователя. Они не включаются в коллекции, историю или экспортируемые команды.
- Изменения действуют для новых запросов и gRPC-рефлексии без перезапуска. Уже отправленный запрос завершает работу со своим снимком настроек.

Прокси HTTP использует обычное соединение с самим прокси и CONNECT для TLS/gRPC. HTTPS-адреса назначения поддерживаются; отдельный TLS-канал до самого прокси (`https://proxy`) и NTLM/Kerberos-авторизация не реализованы. Ошибка явно настроенного прокси не вызывает незаметного перехода на прямое соединение.

## Проверка

Локальные HTTP/SOCKS-прокси и серверы проверяют HTTP/HTTPS, перенаправление с исключением прокси, авторизацию, SOCKS DNS, gRPC-рефлексию и вызов, проверку сертификатов, mTLS и отмену соединения. UI-проверка использует временную базу: автосохранение, DPAPI, отсутствие нового окна, шрифты и Escape. Внешние рабочие API и VPN не используются.

Сборка выпускается только для Windows. Linux-артефакты не пересобирались.
